# 메시지 명세 (protocol.md)

서버와 클라이언트가 주고받는 메시지 약속입니다.
`common/Protocol.java`의 상수와 항상 같아야 하며, **메시지를 추가·변경할 때는 이 문서를 먼저 고치고 상대방 확인을 받은 뒤 코딩합니다.**

방향 표기: `C→S` 클라이언트에서 서버로, `S→C` 서버에서 클라이언트로.
마일스톤: M1(11/15), M2(11/22), M3(11/29).

## 1. 공통 규칙

### 통신 방식
- 제어 채널: 소켓 1개, `BufferedReader` + `PrintWriter`(autoflush), **UTF-8**
- **한 줄 = 메시지 하나.** 형식은 `TYPE|값1|값2|...`
- 수신은 전용 스레드(`readLine()` 루프), 송신은 `synchronized send()`
- `readLine()`이 `null`을 반환하거나 `IOException`이 나면 **연결 끊김**으로 처리
- 포트: `Protocol.PORT`(제어), `Protocol.FILE_PORT`(파일). 값은 팀 합의 후 `Protocol.java`에 기입

### 이스케이프 (모든 필드에 적용)
메시지 생성·해석은 `Message.encode()` / `Message.decode()`만 사용합니다. 다른 코드에서 `|`를 직접 붙이거나 자르지 않습니다.

| 원래 문자 | 전송할 때 |
|---|---|
| `\` | `\\` |
| `\|` | `\p` |
| 줄바꿈 | `\n` |
| `\r` | 제거 |

### 값 형식
| 항목 | 형식 |
|---|---|
| 시간 | `HH:mm` (서버가 붙여서 보냄) |
| 방 종류 | `DEPT`(부서 단체방), `DM`(1:1), `GROUP`(멀티) |
| 활동상태 | `AVAILABLE`(대화가능), `AWAY`(자리비움), `BUSY`(다른용무중), `DND`(방해금지), `OFFLINE`(서버가 자동 설정) |
| 반복 항목 | 개수 `n`을 먼저 쓰고 항목 필드를 `n`번 이어서 씀 |

## 2. 로그인 · 연결 (M1)

| 방향 | 메시지 | 응답 / 설명 |
|---|---|---|
| C→S | `LOGIN\|아이디\|비밀번호` | `LOGIN_OK` 또는 `LOGIN_FAIL` |
| S→C | `LOGIN_OK\|아이디\|이름\|부서` | 로그인 성공 |
| S→C | `LOGIN_FAIL\|사유` | 사유 예: 아이디 또는 비밀번호 오류, 이미 접속 중 |
| C→S | `LOGOUT` | 정상 종료. 서버가 연결을 닫음 |
| S→C | `PING` | 서버가 주기적으로 전송 (M4) |
| C→S | `PONG` | `PING`에 대한 응답 (M4) |

- 로그인 전에는 `LOGIN` 외의 메시지를 처리하지 않습니다.
- 같은 아이디의 중복 접속은 거부합니다.

## 3. 접속자 · 활동상태 (M2)

| 방향 | 메시지 | 설명 |
|---|---|---|
| S→C | `USER_LIST\|n\|(아이디\|이름\|부서\|상태)×n` | 로그인 직후 전체 접속자(부서 구성원 포함) 한 번 전송 |
| S→C | `USER_JOIN\|아이디\|이름\|부서\|상태` | 누군가 접속 |
| S→C | `USER_LEAVE\|아이디` | 누군가 퇴장(오프라인 처리) |
| C→S | `STATUS\|상태` | 내 활동상태 변경 (`OFFLINE`은 보낼 수 없음) |
| S→C | `PRESENCE\|아이디\|상태` | 활동상태 변경을 전체 접속자에게 알림 |

## 4. 대화방 (M2~M3)

| 방향 | 메시지 | 설명 |
|---|---|---|
| S→C | `ROOM_LIST\|n\|(방ID\|이름\|종류)×n` | 로그인 직후 참여 중인 방 목록. **부서 단체방은 서버가 자동 포함** (M2) |
| C→S | `ROOM_CREATE\|종류\|방이름\|m\|아이디×m` | 방 만들기(`GROUP`) 또는 1:1 시작(`DM`, 방이름 빈 값, 상대 1명) (M3) |
| S→C | `ROOM_CREATED\|방ID\|이름\|종류` | 생성 결과. **참여자 전원**에게 전송 |
| S→C | `ROOM_FAIL\|사유` | 생성 거부. 예: 권한 없음(타 부서), 존재하지 않는 사용자 |
| C→S | `ROOM_LEAVE\|방ID` | 방 나가기. `DEPT` 방은 나갈 수 없음 |
| S→C | `ROOM_MEMBERS\|방ID\|n\|(아이디\|이름\|상태)×n` | 방 참여자 목록. 입장·퇴장 때마다 갱신 |

- 이미 같은 상대와 1:1 방이 있으면 새로 만들지 않고 기존 `ROOM_CREATED`를 다시 보냅니다.
- 마지막 사람이 나가면 `GROUP`, `DM` 방은 삭제하고 `DEPT` 방은 삭제하지 않습니다.

### 부서 권한 규칙
- 부서 단체방은 **같은 부서 사람만** 자동 입장합니다.
- 다른 부서와는 **1:1(`DM`)만 허용**합니다. `GROUP` 방을 다른 부서 사람과 만들려 하면 `ROOM_FAIL`을 보냅니다.
- TODO: `GROUP` 방에 **같은 부서 사람만 초대할 수 있게 할지** 팀 합의 후 기입

## 5. 채팅 (M2~M3)

| 방향 | 메시지 | 설명 |
|---|---|---|
| C→S | `CHAT\|방ID\|내용` | 채팅 전송 |
| S→C | `CHAT\|방ID\|보낸이아이디\|시간\|내용` | 방 참여자 전체(보낸 사람 포함)에게 전달 |
| C→S | `EMOTE\|방ID\|번호` | 이모티콘 전송. 번호는 `emo_NN_*.png`의 NN (1~12) |
| S→C | `EMOTE\|방ID\|보낸이아이디\|시간\|번호` | 방 참여자 전체에게 전달 |
| S→C | `SYSTEM\|방ID\|시간\|내용` | 입장·퇴장 안내 |

- 서버는 방 참여자가 아닌 사람이 보낸 메시지를 무시합니다.

## 7. 파일 전송 (M3)

파일 바이트는 제어 채널과 **별도의 파일 소켓**(`FILE_PORT`)으로 보냅니다. 같은 소켓에 섞으면 `BufferedReader`가 바이트를 먹어 깨집니다.

**제어 채널 메시지**

| 방향 | 메시지 | 설명 |
|---|---|---|
| C→S | `FILE_UPLOAD\|방ID\|파일명\|크기` | 업로드 요청. 크기는 바이트 |
| S→C | `FILE_READY\|토큰` | 파일 소켓으로 보낼 준비 완료. 토큰은 1회용 |
| S→C | `FILE_FAIL\|사유` | 거부. 예: 크기 초과, 방 참여자 아님 |
| S→C | `FILE_NOTICE\|방ID\|보낸이아이디\|시간\|파일ID\|파일명\|크기` | 업로드 완료 후 방 전체에 알림 |
| C→S | `FILE_DOWNLOAD\|파일ID` | 다운로드 요청 |

다운로드 요청의 응답도 `FILE_READY|토큰` 또는 `FILE_FAIL|사유`입니다.

**파일 소켓 순서** (`DataInputStream` / `DataOutputStream`)

1. 클라이언트가 접속 후 `writeUTF("UPLOAD" 또는 "DOWNLOAD")`, `writeUTF(토큰)`을 보냅니다.
2. 업로드: 클라이언트가 파일 바이트를 크기만큼 보내고, 서버가 `writeUTF("OK")`로 응답합니다.
3. 다운로드: 서버가 `writeLong(크기)` 후 파일 바이트를 보냅니다.
4. 전송이 끝나면 소켓을 닫습니다.

**제한**
- 파일 크기 상한: TODO 팀 합의 후 기입 (예: 10MB)
- 서버는 `uploads/` 폴더에 저장하고, 저장 파일명은 파일ID로 하여 이름 충돌과 경로 조작을 막습니다.

## 8. 부서 이동 (관리자 서버 창, M3)

관리자 화면은 서버 창이라 **계정 추가·부서 이동 요청 메시지는 없습니다.** 이동한 사용자가 접속 중일 때만 서버가 아래를 보냅니다.

| 방향 | 메시지 | 설명 |
|---|---|---|
| S→C | `DEPT_CHANGED\|새부서` | 접속 중인 사용자의 부서가 바뀜 |
| S→C | `ROOM_LIST\|...` | 새 부서 단체방 기준으로 방 목록을 다시 전송 |
| S→C | `USER_JOIN` / `USER_LEAVE` | 부서 구성원 목록 갱신 |

## 9. 오류 처리

- 모르는 `TYPE`이 오면 **무시하고 로그만 남깁니다.** (한쪽이 먼저 기능을 만들어도 다른 쪽이 죽지 않게 함)
- 필드 개수가 맞지 않으면 해당 메시지만 무시하고 연결은 유지합니다.
- 비밀번호는 로그에 출력하지 않습니다.
